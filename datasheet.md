Frozen: content hash `453058d3225983d2`. Schema: `SCHEMA.md` v1.
Build is deterministic (seed 42; no `PYTHONHASHSEED` dependency).
Generated by `scripts/data/build_dataset.py` (seed 42). Audited by

## 1. Motivation

Training/calibration/evaluation data for a cascaded prompt-injection detector
(Qwen2.5-1.5B Stage 1 routing to LlamaGuard 4 Stage 2). Every example is stored
in its realistic **channel-wrapped** form and tagged with the underlying
**payload family**, so the dataset can answer two distinct questions:

1. **In-distribution detection quality** (`test_in_dist`, deployment base rate).
2. **Cross-channel generalization** — does a family learned in one channel
   transfer to another? (`test_cross_channel`).
3. A secondary **cross-domain transfer** probe (`test_cross_domain`).

Core domain is **Text-to-SQL / data-assistant**, matching the PP Data Assistant
and the OpenMetadata PDP / MATRIX-2358 RBAC threat model.

## 2. Composition

- **3,673** examples across 5 splits.
- Fields per example: see `SCHEMA.md` §1. Only `rendered_input` is shown to the
  model; `channel`, `payload_family`, `domain`, `difficulty`,
  `structural_features` are stratification/audit metadata.

### Channels (`SCHEMA.md` §3)
`direct` (plain user turn) · `document_embedded` (SQL docs, DDL/column comments,
wiki, with concealment variants) · `tool_output` (query rows, `db_row`,
`metadata_description`, Athena/API JSON).

### Payload families (`SCHEMA.md` §2)
`instruction_override`, `exfiltration`, `tool_misuse`,
`system_prompt_extraction`, `rbac_bypass` (SQL-specific, synthetic).

### Coverage — every (family × channel) cell is populated

|---|---|---|---|
| instruction_override | 776 | 148 | 51 |
| exfiltration | — | 78 | 63 |
| tool_misuse | 53 | 80 | 63 |
| system_prompt_extraction | 401 | 30 | 60 |

(`exfiltration|direct` is intentionally absent: exfiltration is an injected-content

### Splits
| split | n | inj. rate | purpose |
|---|---|---|---|
| train | 2008 | 0.50 | balanced detection training |
| cal | 523 | 0.46 | calibration; difficulty-weighted (hard/ambiguous oversampled) |
| test_in_dist | 523 | 0.15 | realistic deployment imbalance |
| test_cross_channel | 366 | 0.50 | held-out (family×channel) cells + matched negatives |
| test_cross_domain | 253 | 0.59 | non-sql (browsing/calendar/email), never trained |

Cross-domain examples use domain-appropriate scaffolding (email `read_email`,
calendar `get_calendar_event`, browsing HTML), not SQL rows.

**Cross-channel holdout cells** (reserved entirely, zero train leakage):
`(exfiltration, document_embedded)`, `(tool_misuse, direct)`,
`(system_prompt_extraction, tool_output)`. Each family is still seen in *other*
channels during training, so the test isolates channel transfer.

## 4. Collection & preprocessing
- Loaders map each source to (channel, payload_family, difficulty); see
  `src/data/loaders/` and `src/data/taxonomy.py`.
- Channel-faithful rendering: `src/data/rendering.py` (payload verbatim-preserved,
  checked by `payload_preserved`; zero-width insertion keeps every visible glyph).
- Hard negatives: `src/data/negatives.py` — channel-matched, reusing
  benign-plausible structure (JSON shapes, imperative mood, HTML/DDL comments,
  quoted attacks for discussion) so structure alone cannot be exploited.
- Synthetic fill + ambiguous + cross-domain: `src/data/synthetic.py`.
- Near-duplicate dedup (Jaccard ≥ 0.9 on 5-gram shingles, bucketed by
  channel×label): `src/data/preprocessing/dedup.py`.

## 5. Audit results (`scripts/data/audit_dataset.py` → `data/audit/`)
- Schema re-validation: **0 invalid**.
- Cross-split leakage (all pairs, normalized text): **0**.
- Structural anti-cheating: every benign-plausible structural feature
  (`json_field`, `db_row`, `metadata_description`, `html_comment`, `ddl_comment`,
  `code_block`, `quoted_text`, `chunk_position`) appears in **both** classes.
  Inherently-malicious concealment (`zero_width`, `white_on_white`, `tiny_font`)
  is injection-only by design — hiding text *is* the signal.
- Manual-audit sample: `data/audit/manual_audit_sample.jsonl` (6/channel/split).

## 6. Recommended uses
- Train + calibrate Stage 1 on `train` / `cal`.
- Report in-distribution detection at deployment base rate on `test_in_dist`.
- Report cross-channel generalization on `test_cross_channel`.
- Report cross-domain transfer on `test_cross_domain` (never train on it).

## 7. Known limitations
- **Single-shot only**: no multi-turn / conversational injection (`SCHEMA.md` §5).
- **English-only**, text-only (no multimodal).
- **Benchmark→SQL re-rendering**: benchmark payloads are projected into the SQL
  domain; some retain generic (non-SQL) action verbs (e.g. "email"), which is
  realistic for poisoned content but not strictly SQL-native.
- **`rbac_bypass` is fully synthetic** (no public benchmark covers it); template
  variety is bounded — treat absolute rbac numbers as indicative.
- **HackAPrompt via public mirror** (canonical dataset is gated); the mirror
  exposes a combined `text` field, so the injected segment is heuristically
  extracted and may include minor app-framing residue.
- **External-eval contamination**: positives derived from InjecAgent/BIPIA/etc.
  mean this dataset should not be used to *evaluate* on those same benchmarks'
  held-out splits. Internal cross-split leakage is 0.
- **`ambiguous` difficulty is thin** (~19 in `cal`); calibration leans on the
  larger `hard` bucket.

installed and `WANDB_API_KEY` is set (otherwise a local freeze is written to
